# Revenium CLI Drift & Coverage Report

**Purpose:** This is the git-tracked record of where the Revenium CLI and the three Revenium
OpenAPI specifications — platform, metering and analytics — disagree: every endpoint deliberately
skipped as non-CLI-appropriate, every command or flag that backs a deprecated or removed upstream
endpoint, every asymmetry between what the CLI sends and what a schema declares, and the decision
recorded against every actionable gap the audit reports. It lives under `docs/` so it survives
outside the planning tree and is readable in a fresh clone. The public CHANGELOG has pointed at
this path since v1.3.0.

**Current as of v1.7.** The finding tables in sections 1, 2 and 3 are **generated**. A coverage
audit in this repository joins the three OpenAPI documents against the CLI's own source tree and
writes those tables between `<!-- BEGIN GENERATED -->` and `<!-- END GENERATED -->` markers; a
companion check regenerates them in memory and fails if what is committed no longer matches what
the audit produces. The numbers here were taken from the specification cache fetched
**2026-08-23** and audited against the source tree on **2026-09-09**, at the close of the v1.7
phase that closed out the carried live-environment items, whose dispositions the two tracked
SQUAD-11 and MTR-07 rows in section 1 now carry. The phase before it, audited
**2026-09-07**, added the team-settings, session-attribution and org-unit-preview commands. Earlier revisions of
this report were compiled by hand from findings recorded across phases, with no live verification;
that is no longer how the tables get here, which is the whole point of the change. Everything
outside the markers is hand-written judgement. The two halves are kept apart deliberately, and
sections 2 and 3 say exactly where the line falls and why: some findings here can never be derived
by a tool, and a generator that owned a whole section would delete them.

**What the audit measured on that run.** 178 of 364 specification operations are called by the CLI
(48.9%); 60 endpoint gaps are actionable and 126 endpoints are recorded deliberate skips; 23 CLI
paths are defined by no specification. At field level, 1,636 raw findings reduce to **300
actionable** and 1,335 suppressed, drawn over 2,083 specification fields, 539 CLI fields and 201
called endpoints — 278 properties a specification declares and the CLI never sends (27 of them
required), and 22 keys the CLI sends that no schema on that endpoint declares. Section 1.1 records
a disposition for each of those rows, but the set is **not** complete: 6 endpoint rows and 10 field
rows are currently untriaged and carry none. Those sixteen are a single inherited batch from the
two phases that added the agentic-jobs economics commands; they are named by the audit's own triage
gate and are deliberately held for one pass rather than triaged piecemeal.

The count of CLI paths no specification defines is the figure that moved furthest, from 5 to 23,
and it is not drift in the ordinary sense. Nine of those paths are commands built deliberately
against the development platform document while the production document still lags it, and each one
carries a dated, reasoned entry in the machine-readable rationale file recording that it is an
accepted risk rather than an unnoticed dead command. They resolve by the production API shipping the
endpoints, at which point the entries are reported stale and get deleted.

**Reading the references.** This report carries pointers rather than restatements, so detail
cannot drift out of sync with its source. Some of those sources live only in the CLI's internal
development repository, and each is marked `(internal: …)` — the reference is real and
deliberately unreachable from here, and its contents are never quoted. Everything under
`.planning/` is internal, as are three sibling files under `docs/`: `docs/analytics-coverage.md`,
`docs/endpoint-skip-rationale.json` (the machine-readable file the generated tables render from)
and `docs/api-endpoint-inventory.tsv`. Of the `docs/` tree, only this report is published. Paths
under `cmd/` and `internal/` name source files that resolve in the public repository; `tools/` and
`scripts/` are internal maintenance tooling.

**Recommendation stance:** Recommendations in this report are non-binding suggestions meant to
save the next roadmap review a re-analysis pass — the project's standing decision to flag
deprecations and removals rather than auto-delete them (internal: `.planning/PROJECT.md`) is
unchanged by this report, and nothing here authorizes removing a command or flag. One stated
exception: the credentials rebuild (section 2, V2-03) carries facts only and no technical
recommendation, because it needs a product/API-owner decision before any implementation work
starts.

## Shipped since this report was first assembled

This report was first assembled for the v1.3.0 release. Two releases shipped between that assembly
and this revision, and neither was reflected here until now.

- **v1.4.0 — skill tracking.** `meter completion` accepts `--skill-name`,
  `--skill-invocation-trigger`, `--skill-source`, `--skill-kind`, `--skill-plugin-name` and
  `--skill-marketplace-name`, each sent only when passed. These properties are specific to the
  completion endpoint; the audio, image, video and tool-event schemas do not declare them, so no
  other `meter` subcommand exposes them.
- **v1.5.0 — ticket attribution.** `meter completion|audio|image|video` accept `--ticket-id`, sent
  as `ticketId` only when passed, for attributing cost to an external ticket or issue.

**`ticketId` is present on all four AI metering endpoints** — `POST /v2/ai/completions`,
`POST /v2/ai/audio`, `POST /v2/ai/images` and `POST /v2/ai/video` — and that is a statement this
report can check rather than assert. In one direction, all four commands register and apply the
flag through one shared helper: `cmd/meter/completion.go`, `cmd/meter/audio.go`,
`cmd/meter/image.go` and `cmd/meter/video.go` each call `AddTicketFlag` and `ApplyTicketFlag` from
`cmd/ticket.go`. In the other, the metering specification declares `ticketId` on all four request
bodies. So the property produces **no finding row in either direction on any of the four
endpoints** — it is absent from the 277 properties a specification declares and the CLI never
sends, and absent from the 13 keys the CLI sends that no schema declares. A covered property
generates no row, and that absence is the evidence.

`meter tool-event` deliberately does not expose the flag: the tool-event schema does not declare
the property.

regression risk for no gain. If it does not, `--is-realtime` is already a silent no-op and the

flag spelling stays stable, so no operator's script breaks. The generated row's note names the

actually decided was to record the asymmetry and not to rename.
